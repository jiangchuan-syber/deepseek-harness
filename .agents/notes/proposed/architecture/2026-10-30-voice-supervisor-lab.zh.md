# Agent Note: Voice supervisor laboratory

Status: proposed

[English](2026-10-30-voice-supervisor-lab.md) | 中文

## 问题

如果语音客户端在等待整个 Agent 空闲时拒收输入，就无法在原生子任务执行期间持续进行主会话。复制任意模型提供方正文用于朗读，也无法区分接话、主要回答和打断后的未播内容。

## 提案

保留原生 Agent 循环和委派运行时。通过 dsh 配置挂载可选实验插件，将消息接收和结果收集分离，观察主会话和子任务的原生事件。接话生成和音频送达由外部实验客户端控制。虚拟送达回执作为输入上下文记录，不改写原始回答日志。

[实验计划](../../../../prototypes/voice-supervisor/docs/PLAN.zh.md)负责定义实验和验收矩阵，分别记录真实 API 与模拟识别、播放的测量。正式配置不导入此原型。

## 考虑过的替代方案

**修改 Agent 循环。**原生收件箱和后台委派已经存在，在验证客户端集成前修改生命周期会增加风险。

**把整个模型提供方响应流复制到语音。**这会混淆后台和主会话输出，也不能确定实际播放了什么。客户端改为选择主会话回答，并独立记录音频送达。

**把接收当作完成。**子任务仍在运行时可以接收输入。实验要求原生子任务完成前主会话实际回答，并独立校验执行产物。

## 验收条件

真实 DeepSeek 运行展示原生子任务执行期间的主会话回答、经过检查的校验产物、接话先于回答的顺序，以及进入下一次主会话输入的部分播放回执。离线测试拒绝旧周期音频并正确报告模型失败。报告说明模拟部分和能力限制。

## 风险

模型的工具选择可能变化。受控等待只提供重叠窗口，不代表模型性能。虚拟字符对齐不能替代设备采样回执。隔离测试给合成任务会话完整权限，不得接收不可信任务文本。
