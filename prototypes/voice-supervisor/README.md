# Voice supervisor laboratory

English | [中文](README.zh.md)

This opt-in prototype acknowledges input through an independent bounded request with thinking off, while a persistent Harness parent uses max reasoning effort to delegate native child work and return results through an interruptible speech queue. It does not replace the installed desktop application.

## Documents

The local runtime exposes authenticated `/health/live` and `/health/ready` endpoints. Readiness requires recent native polling; a dead child or prolonged polling failure makes liveness fail. SSE publishes an immediate connection comment and closes when the native process exits. Diagnostic output rotates independently of durable Session logs. Windows deployment and owned-process recovery are managed by the enclosing project's `server/service_manager.py`, not by this optional prototype.

## Run

Requires Node >=24.9, the repository's pinned pnpm, and `DEEPSEEK_API_KEY` in the launch environment. `VOICE_MODEL` defaults to `deepseek-flash`. The interactive runner uses an independent tool-free `off` request for acknowledgements and the persistent native parent with `max` for execution decisions; native children inherit compatible parent model and effort settings unless overridden.

From the repository root:

```sh
pnpm install --frozen-lockfile
pnpm run build:artifacts
node --test prototypes/voice-supervisor/tests/*.test.mjs
pnpm exec oxlint -c prototypes/voice-supervisor/oxlint.json --disable-nested-config prototypes/voice-supervisor
node prototypes/voice-supervisor/interactive.mjs
```

The runner creates an isolated home and fixture workspace under `.runs/`, launches the supported `dsh --profile web` source entry with the overlay, and prints an authenticated loopback page URL. It keeps credentials in the process environment. The fixture worker waits 22 seconds, hashes `sample.txt`, and writes `worker-result.json`; this wait creates an interaction window, not a performance measurement.

## Manual test page

Keep the printed page open. Submit the sample task, interrupt virtual playback, and send a follow-up while the parent is thinking or a child is running. Acknowledgements use a bounded request journal; execution decisions belong to the persistent native session. The page accepts text as simulated ASR input; playback uses a virtual character clock and produces no sound.

The ESP32 bridge separately supplies real ASR, TTS, PCM transport, and whole-chunk device receipts. Its four-module workbench displays the quick stage, deep processing, queued input, native tool traffic, child settlement, and actual playback evidence. Speech and model work can progress concurrently.

The interface binds to `127.0.0.1` and authenticates API requests with a local token. Ctrl+C stops the runner. `VOICE_LAB_RESUME_DIR` with the corresponding `VOICE_LAB_SESSION_ID` resumes a retained isolated home and parent; fixture files are not overwritten. Normal startup creates a fresh isolated session. Do not use this development runner for untrusted tasks.

## Integration behavior

Input admission returns HTTP 202 and a request ID. The quick lane runs independently of native deep work. Each quick request uses its own short system, at most 1200 recent conversation characters and 600 latest-input characters, effort `off`, no tool declarations or executor, and 64 output tokens. It stops at one sentence or 30 Unicode characters. These limits are configurable in `overlay.yml`. The runner forwards the quick speech events before acknowledging `/continue`; only then does the native phase queue receive the original untruncated input, acknowledgement and playback receipt. It may merge pending continuations. Failed admission is visible and does not report execution as started.

Quick speech uses a natural response rather than a mandatory opening. A stop before usable text is a visible quick failure with an empty continuation acknowledgement; it does not fabricate speech. The bridge's fixed wake cue remains a separate device event. Natural quick text stays in recent context and the deep continuation; this does not establish that it was played.

The native parent Session identifies quick cancellation scope; each recording's `voiceSessionId` remains turn metadata. New input retires older queued acknowledgements and aborts the running acknowledgement in that parent only. Superseded inputs still continue to deep processing with an empty quick reply; they do not cancel the parent or its children. Stale providers cannot publish later text, completion or recent-context updates. The overlay sets `quick.cancelGraceMs: 50` and `quick.maxOutstanding: 2`: after the grace period an unresolved old call remains owned while a new call can start within the total outstanding-call budget. Saturation reports an explicit quick failure and retains the original goal. Cleanup counts remain visible, and shutdown waits for owned calls to settle. This does not promise provider cancellation latency or physical speech within one second. Custom overlays must add both keys; see the [upgrade guide](../../docs/upgrade-guide/v0.2.2-alpha.2/voice-quick-cancellation-budgets/guide.md).

The native parent uses the overlay's `supervisorReasoningEffort: max` on startup and between execution stages; quick calls do not change its model selection. Model events expose request timing and first-delta categories. The authenticated `/speech-events` SSE additionally forwards visible parent text deltas, generation IDs and message settlements; private reasoning and tool arguments are not forwarded. Both explicit agent messages and automatic settlement notices establish child-result receipt. Child output is summarized by the parent before speech.

Continuation instructions reserve direct execution for very simple operations and state checks, and delegate reasoning or multi-step work. The parent checks a child brief against the current goal, evidence and side effects, then reports relevant results, uncertainties and decisions without reading the brief verbatim. Missing evidence is not verified success; interrupting speech does not cancel the child. These are model instructions, not additional execution isolation or expanded tool permissions.

Quick request inputs and responses are recorded in the private `quick-requests.jsonl`; they do not enter the main request history until the deep continuation. Phase events and admissions are appended to a local queue journal. Generated speech is appended to an outbox. Pending native messages are supplied as unconfirmed delivery context on later inputs. Only all real-device pieces acknowledged as completed settle a native message; virtual playback does not confirm real-device delivery. Unfinished requests are not automatically replayed after restart.

The authenticated POST `/quick-probe` measures the same quick call with a fixed synthetic 1200-character history; it does not speak, dispatch work, or update conversational memory. It requires an idle quick lane, rejects overlapping probes with HTTP 409, shares the provider-call budget and is cancelled when real input arrives. Unresolved diagnostic cleanup remains counted. Its TTFT uses a monotonic clock around the application model stream, not a provider-only inference timer. `verify-staged.mjs` requires a fresh isolated runner and checks quick request journals, native deep headers, child completion and the independently verified worker artifact. It must not run against a retained user session.

## Limitations

The overlay reads `VOICE_SIMPLE_CONTROL_CONFIG` JSON, defaulting to `{ "enabled": false }`. Enabling `simpleControl` requires positive `budgetMs` and `capacity`, plus an explicit `provider`: `kind: miio-lamp` composes the private lamp adapter; `kind: composed` accepts a programmatically supplied provider instance. The lamp adapter requires explicit identity, Python, workspace and time limits; execute mode additionally requires `allowWrite` and `cooperativeControlReady`. Construction performs no I/O. The first admitted command prepares and verifies identity asynchronously within its original deadline, without delaying quick speech. Only lamp power is supported by this adapter; unsupported actions stay with the parent. The general lane validates lamp brightness 1–100 and AC temperature 16–30 without clamping; unresolved, duplicate or non-3625 device mappings cannot execute. Quick speech remains tool-free and makes no control decision.

`node --import tsx/esm prototypes/voice-supervisor/tests/outer-control-integration.mjs` is an explicit offline, cross-repository fixture. Set `VOICE_CONTROL_TEST_PYTHON` to Python and `VOICE_CONTROL_BRIDGE_SOURCE` to the candidate ESP32 `server` directory containing the program-control consumer; optionally set `VOICE_CONTROL_OUTER_REPORT`. It runs the actual interactive HTTP/SSE runner, plugin, private Python fixture broker, bridge generator and FlowTrace in owned temporary processes. Only the native launcher/LLM boundary is replaced; other child launches and non-owned fetches fail closed. Public inputs cover exact voice/request/goal propagation while Max stays busy, quiet success, authorization, unknown write/read timeouts without rewrites, and an old fact that cannot be relabeled as a newer turn. No production config, cloud, audio or real appliance is used. Full Cordis bootstrap/persistence, model semantics, visual rendering and physical latency remain outside this fixture. Reports and synthetic temporary workspaces are retained for inspection, not committed.

`node prototypes/voice-supervisor/tests/native-brief-integration.mjs` is a separate keyless native-structure diagnostic. Run the official `pnpm run build:artifacts --serial` first in an isolated checkout with owned dependencies and output directories. It launches the real CLI Web profile, Cordis, tool and child Agent against one synthetic loopback Messages provider, with a private `DSH_HOME` and workspace. Launcher `appReady` and the authenticated state endpoint establish startup; the voice plugin's earlier ready file does not. The case checks child dispatch, inbox receipt and a separate parent generation containing a newly written summary. Synthetic responses prove communication structure, not model judgment; the child Agent runs in-process and does not prove OS-process isolation or forced task termination.

The native diagnostic allows its pinned transpiler, one reviewed installed Git binary's exact workspace-location read and its hashed Windows Job bootstrap in the owned directory, and the owned provider port. The rules verify realpath, binary SHA and every argument; Windows compares canonical paths without case sensitivity. It denies other subprocesses and non-owned network requests, retains bounded denial details privately, and reports structural, guard and lifecycle outcomes separately; an intercepted call makes the overall case fail even if an optional plugin catches the exception. Private IPC requests the real launcher's `appExit`; forced termination or unfinished expected reads fail the case. Expected read-process exits are recorded separately and do not prove OS isolation for Agents. Temporary logs, request bodies and report files remain local. Do not run this diagnostic against a retained user session or describe it as a cloud, audio, browser-visual or physical-latency acceptance test.

Control jobs execute beside quick requests without waiting for the Max parent and are not submitted as ordinary deep continuations. The provider resolves an approved unique resource, writes once and performs a separate fresh read with a query identity; a matching protocol read is distinct from independent physical-effect evidence, particularly for infrared AC control. Same-resource writes serialize, different resources may overlap, and a newer goal makes old queued work obsolete. Unknown writes are not retried blindly. The private queue journal flushes control snapshots; after restart an explicit repeated command reconciles uncertain work by reading, without rewriting or claiming its original latency. This is cooperative scheduling, not an arbitrary-shell sandbox.

Native `parent.inject()` receives an internal execution notice without waking a turn; successful actions do not produce a second success utterance. A current rejected or unknown result gets a separate report-only parent turn, not another execution request. Plugin `/state.controls` and `control.state` expose command identity, goal version, execution and readback facts. The authenticated outer runner also exposes `/control-events` SSE, `/state.controls`, and `/trace.state.controls`; the last two share a bounded metadata projection with controller source identity and sequence. Live control events update it before the next native poll. These are program facts, never fabricated model tool calls; consumers match the exact request and voice session. Local budgets and fixtures do not establish the physical-PTT-to-readback three-second requirement.

`capacity` bounds active admissions, including queued, preparing, executing and reconciling promises. Actual settlement releases the slot even after failure; a cancelled queued promise remains owned until it settles. Terminal and unknown history retains its deduplication facts. State contains active entries plus recent history, limited to `capacity` (at most 256 facts in the outer projection). Authenticated `GET /control-result?commandId=<exact-id>` reads one retained fact with its original command/voice/goal/clock; it does not start a provider, reconcile, execute or rewrite that identity. Unknown recovery remains read-only. The in-memory history and append journal still grow; active admission and snapshot bounds are not a total storage bound. A durable history index/retention design remains separate work; deleting terminal IDs would permit replay.

Authentication and input validation precede admission. An ordinary deep-handoff backlog cannot consume a supported control job's separate bounded admission budget; control saturation returns HTTP 503. Unsupported controls and ordinary language retain the original deep-handoff limit. The offline outer fixture also fills 32 real handoffs while its event observer is delayed, verifies the independent control path and overflow failures, and reconnects bounded SSE replay by its actual sequence. The event ring and native control snapshot have different documented bounds; neither is a durable action ledger.

Quick replies can run during deep work; new deep decisions still wait for the serialized native parent. Long execution should use children. The v2 Python bridge commits visible text incrementally to one Qwen PCM task per utterance. It requires matching v2 device firmware; the legacy device path still consumes completed messages. Only device consumption confirmation settles delivery. The old `run-live.mjs` exercises the earlier independent-front scenario and is not the staged runner's acceptance command.

Queue journals retain evidence but do not provide crash-safe task replay or autonomous delivery after an empty recording. Undelivered older output is supplied for the parent's review rather than replayed automatically. Firmware v2 reports conservative consumed-sample cursors; word alignment is unavailable. Prompt directory constraints are not an operating-system sandbox; context capacity and compaction remain native Harness behavior.
