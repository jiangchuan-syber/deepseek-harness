# 基础版本验证报告

日期：2026-10-30。基线版本：`dsh-v0.2.2-alpha.2`。模型和原生任务是真实执行，ASR、TTS 和播放为虚拟实现；未连接 ESP32。

## 结论

三角色基础流程已经成功跑通一次，真实场景的 9 项断言全部通过。无需改写 Harness 核心循环：原生后台子任务、steer 输入及子任务完成通知已经具备需要的基础能力，改造集中在可选的语音桥与客户端队列。此结论只覆盖受控实验，不代表生产设备已完成改造。

原型入口、命令、限制见[运行说明](../README.zh.md)，预先定义的验收见[改造计划](PLAN.zh.md)。完整数值和合成对话见[真实运行结果](evidence/live-result.json)，原生事件摘要见[执行轨迹](evidence/trace.json)，音频调度见[播放轨迹](evidence/playback.jsonl)。

## 验收证据

| 场景 | 实际结果 |
|---|---|
| 小模型快速接话 | 两轮均使用真实 deepseek-flash，thinking=disabled，未调用工具 |
| 主调度器委派 | 原生 spawn 子任务启动，执行固定工作目录内的校验脚本 |
| 子任务运行中继续对话 | 主会话在 child.end 前产生【进度】回答；不是只有 accepted 回执 |
| 自然语音交接 | intro.completed 先于 answer.started；离线测试也覆盖正式答案提前可播时不硬切接话 |
| 按键打断 | 虚拟播放器在“我已经安排”后停止，其余原始回答单独标为未播 |
| 上下文送达 | 下一轮原生 user/message 含播放回执；主调度器实际回复正确引用已播前缀及未播后缀 |
| 后台真正完成 | 生成 worker-result.json，独立计算 SHA256 一致；样例 34 字节 |
| 调度器汇报结果 | 最终回答包含与文件一致的完整 SHA256 |
| 事件传输 | 无轮询错误；已确认测试 Harness 进程退出，未留下本次 worker 进程 |

虚拟回执能确认模拟时间轴播放的字符，不能确认用户理解。模型原始完整回答仍保留在独立 Harness 日志中；下一轮通过显式送达记录区分已播与未播，没有改写会话文件。

模拟 ASR 直接输入最终文字，识别延迟为 0；模拟 TTS 延迟为 0，字符对齐已知；播放速率为每秒 9 字。最后的播放清空通过虚拟时间推进完成。0.40 ms 是本机队列操作耗时，不是按键、网络或实际喇叭停音延迟。工作脚本人为等待 22 秒，以提供并发验证窗口，该等待必须从性能分析中单独识别。

正式答案尚未生成时，系统仍有空档；本次 2.34 秒不能描述为无缝零等待。接话层改善首次反馈，并没有消除主调度器的模型与委派耗时。首次接收包含新会话冷初始化，不能与后续 6.23 ms 当作同分布样本。本次是一次功能验证，不提供 p50/p95 或稳定性承诺。

## 开发中发现并修复的问题

1. 新工作副本缺少客户端产物，源码 Web 组合无法加载；执行完整 artifacts 构建后修复。
2. Cordis 的插件 name 不接受配置表达式；运行器将受控相对模板转换成隔离运行目录内的绝对路径覆盖文件。
3. 遥测关闭值需要 DISABLED，使用 OFF 会导致插件配置报错；已修正。
4. 测试曾把进度里引用的“【结果】”字样误认作最终结果；改为匹配回答开头，并保留独立文件校验，失败运行未计为通过。
5. 接话模型曾把进度询问变成反问；明确约束不得提问，成功运行两轮均为简短确认。

## 下一步边界

本次交付已经覆盖电脑虚拟环境的最小闭环。实际产品仍需接入 ESP32 的播放采样回执与真实 TTS 对齐，限制调度器口语长度，完善长期会话、任务恢复与更广泛的延迟统计。默认桌面配置和现有设备固件均未替换。原生子任务可以先通过消息把已验证的结果交给主会话，随后才结束生命周期；因此最终答案应在成果验证后产生，而不强制等待生命周期结束事件。
