# 语音调度器实验室

[English](README.md) | 中文

本可选原型以独立有界请求关闭思考接话，由持续 Harness 主会话以 max 思考强度决策、按需委派原生子任务，并通过可打断语音队列返回结果。它不替换已安装的桌面应用。

## 文档

本地运行器提供需要鉴权的 `/health/live` 和 `/health/ready`。就绪要求近期成功轮询原生状态，子进程退出或长时间轮询失败会导致存活检查失败。SSE 建连立即发送注释，原生进程退出时关闭；诊断日志与持久会话分开轮转。Windows 部署和所属进程恢复由外层项目的 `server/service_manager.py` 管理，不由本可选原型自行看护。

## 运行

需要 Node >=24.9、仓库固定版本 pnpm 和启动环境中的 `DEEPSEEK_API_KEY`。`VOICE_MODEL` 默认为 `deepseek-flash`。快速回应使用独立无工具 `off` 请求，持续原生主会话使用 `max` 执行决策；子代理未单独覆盖时继承兼容的父模型与推理强度。

在仓库根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm run build:artifacts
node --test prototypes/voice-supervisor/tests/*.test.mjs
pnpm exec oxlint -c prototypes/voice-supervisor/oxlint.json --disable-nested-config prototypes/voice-supervisor
node prototypes/voice-supervisor/interactive.mjs
```

运行器在 `.runs/` 中创建隔离 home 与样例工作目录，使用 overlay 启动受支持的 `dsh --profile web` 源码入口，并打印带本地鉴权的回环页面 URL。凭据保留在进程环境中。样例 worker 等待 22 秒，计算 `sample.txt` 的哈希并写入 `worker-result.json`；等待用于创造交互窗口，不作为性能测量。

## 手动测试页面

保持打印出的页面打开。提交样例任务，打断虚拟播放，并在主调度思考或子任务运行时补充话语。快速回应使用有界请求日志；执行决策属于持久原生主会话。页面接受文字模拟 ASR 输入；播放采用虚拟字符时钟，不发出声音。

ESP32 桥另行提供真实 ASR、TTS、PCM 传输和整段设备回执。四模块工作台显示快速阶段、深度处理、输入排队、原生工具流、子任务结束通知及实际播放证据。声音播放与模型工作可以并行。

接口绑定 `127.0.0.1`，通过本地 token 鉴权。Ctrl+C 停止运行器。`VOICE_LAB_RESUME_DIR` 配合对应 `VOICE_LAB_SESSION_ID` 可恢复保留的隔离 home 与主会话；不覆盖样例文件。正常启动创建新的隔离会话。不要用本开发运行器处理不可信任务。

## 集成行为

输入接纳返回 HTTP 202 和请求 ID。快速通道独立于主会话深度处理，使用独立短 system、最多 1200 字符近期对话和 600 字符本轮输入，关闭思考，不带工具声明或执行器，输出预算 64 token；一句话结束或达到 30 个 Unicode 字符即停止。限制可在 `overlay.yml` 调整。运行器先转发快速语音事件，再确认 `/continue`；随后主会话队列一次接收原始未截断输入、快速回应和播放回执，可以合并待执行续接。续接不能入队时显示错误，不声称已开始执行。

快速接话使用自然回应，不强制固定开场。尚无可播文字就停止时，明确记录接话失败并以空接话续接，不编造语音。桥端固定唤醒提示仍是独立设备事件。自然接话原文保留在近期上下文和深度续接中，但这不表示它已播放。

原生主调度在启动和执行阶段之间使用 overlay 的 `supervisorReasoningEffort: max`；快速调用不改变它的模型选择。模型事件提供请求计时和首增量类别；已鉴权的 `/speech-events` SSE 另行推送父会话可见正文增量、生成身份和消息完成事件，不转发内部思考正文或工具参数。主动代理消息和自动结束通知都可确认子结果接收。子输出先由主调度整理，再交给语音。

续接指令限定主调度直接处理极简单操作和状态检查，把推理或多步骤工作委派出去。主调度核对子代理简报与当前目标、证据及副作用，再按相关性汇报成果、不确定性和待决项，不照读简报。缺证据不算验证成功；打断语音不取消子任务。这些是模型提示规则，不是新增执行隔离或扩大工具权限。

快速请求的实际输入和回复保存在私有 `quick-requests.jsonl`，深度续接时才将输入和短回复交给主会话。阶段事件和接纳记录追加到本地队列日志，生成的语音追加到待播记录。后续输入将待确认的原生消息作为未确认送达上下文。只有真实设备对某条原生消息的全部片段确认完成，才确认该消息送达；虚拟播放不确认真实设备送达。重启不自动重放未完成请求。

已鉴权 POST `/quick-probe` 使用固定合成的 1200 字符历史测量同一快速请求，不播放、不派发任务、不更新对话记忆。TTFT 用单调时钟测应用侧模型流，不能当作纯服务端推理耗时。`verify-staged.mjs` 要求全新隔离运行器，检查快速请求日志、原生深度请求头、子代理结束和独立核对的 worker 产物；不得对保留用户会话运行。

## 限制

可选 `simpleControl` 配置缺省关闭。启用需显式给出正数 `budgetMs`、正整数 `capacity` 和已组合的 `voiceDeviceControl` provider；当前不提供真实设备 provider。夹具控制通道只识别完整、明确的单设备电源指令、台灯亮度 1–100 或空调温度 16–30；其他表达仍交主调度。越界直接拒绝，不截成范围内值；设备映射不明确、不唯一或不属于尾号 3625 的家均不执行。快速接话仍无工具，不作控制判断。

控制任务与 quick 并行，无需等待 Max 主会话，且不作为普通深度续接重复提交。Provider 解析已批准的唯一设备，写一次，再独立发起带查询身份的新读回；协议读回匹配与物理生效证据不同，红外空调尤其如此。同一物理设备串行，不同设备可并行；新目标使旧的排队动作失效。写结果未知不盲重试。私有队列日志 flush 控制快照；重启后显式重复请求仅用读回核对不确定动作，不重写，也不声称原先时延已知。这是协作式调度，不是任意 shell 的安全沙箱。

原生 `parent.inject()` 只注入内部执行事实，不唤醒新轮次；成功动作不额外播报确认。仍属当前目标的拒绝或未知结果另排仅汇报的主会话轮次，不重新派发动作。插件 `/state.controls` 和 `control.state` 事件记录命令身份、目标版本、执行与读回事实；外层运行器另提供鉴权 `/control-events` SSE、`/state.controls` 和 `control.<status>` 轨迹，按命令 ID 关联，不借用最新请求。这些是应用事件，不是模型工具调用消息。Python 桥/网页消费端和真实设备 provider 仍需单独接线。控制通道的单调时钟预算不等于完整的物理松键到有效读回三秒验收。

快速回应可在深度任务运行时生成；新的深度决策仍等待串行原生主会话。长时间执行应使用子代理。v2 Python 桥将可见正文增量提交到每次连续发言独立的千问 PCM 任务，需要配套 v2 固件；旧设备路径仍使用完整消息。只有设备消费确认才能确认送达。旧 `run-live.mjs` 验证早期独立前台场景，不是分阶段运行器的验收命令。

队列日志保留证据，但不提供崩溃后安全任务重放，也不支持空录音后自主送达。旧的未送达输出交由主调度重新判断，不自动重播。v2 固件报告保守消费样本游标，尚无词级对齐。提示词中的目录约束不是操作系统沙箱；上下文容量与压缩继续使用 Harness 原生行为。
